## How to read it

The three columns are the three application types of D114: **Console** (`CampertronConsole` without `--web`: the menu of `Menu.cs`, email or ntfy mode of `MonitoringConsole`, the container's start), **GUI** (`CampertronGUI`) and **Web** (`CampertronConsole --web`, the pages of `CampertronWeb`).
Each cell starts with one class:
- **Complete:** the application has a practical workflow with its validation, persistence, failure handling and tests.
- **Partial:** a workflow exists but misses part of the capability (named in the cell).
- **Read-only:** the application shows it and cannot change it.
- **Indirect:** the application acts on it only as a side effect of another workflow (a start that refuses, a warning).
- **File-only:** the user can do it only by editing a settings or search file in a text editor (or with another application).
- **Missing:** no workflow at all.
- **N/A:** not applicable, by an approved rule (named) or because Campertron has no such setting (said).

A shared library service alone never makes a cell Complete: the application must expose it. For example, `ConfigEditSession` and the settings forms exist in `CampertronLibrary`, and the console's settings cells stayed File-only until its interactive console exposed the forms (phase 7, D122; phase 7a, D123).

**Dimensions:** 15 categories, 236 capability rows, 3 application columns: 708 classified cells. The counts by class are in §Summary by application.
