### V011-3 Coordinated correction of the autoRun and "startup" terminology
Correct misleading `autoRun` and "startup" wording consistently, as the implementation evidence supports: GUI labels, tooltips, accessible names, diagnostics, the directly affected tests, README wording, screenshots and the current AI-context records.
**The wording is decided** (the maintainer, 2026-11-18; implemented by Phase C, D63): the canonical term for a search with `autoRun: true` is "Enabled (autoRun)", and its negative is "Not enabled" (instead of "Disabled"). Explanations are specific to their context, following the verified behavior below; no single sentence is forced across the GUI, the interactive console's Search and Email mode. The implementation settles the exact sentences.

Verified behavior that the wording must describe:
1. Starting the interactive console does not itself run searches.
2. Choosing Search in the interactive console reads the search files each time and runs the searches with `autoRun: true`.
3. Email mode reads the search files once, when it starts, and then runs the `autoRun`-enabled searches every minute.
4. A change to the search files after Email mode started needs a restart of Email mode.
5. The GUI runs no search merely because it starts.
6. In the GUI's Results tab, `autoRun`-enabled searches are selected by default.
7. Searches without `autoRun` run when they are selected manually in the GUI.
8. With no search file, the console creates and runs its example search the next time it searches, not at a generic application start. (Since D65, after `v0.1.1`, only the console's Search does; email mode stops with an error.)

A host-user recipe was verified (D57), but it is tied to open questions #10 and #27 and the choice is the maintainer's. Since D70 (on `master` since PR #107) the GUI recommends the password file over the plain-text password, but never clears or migrates a plain-text password. - **The monitoring lock's platforms (open question #49):** on Linux the lock (D90) was run in the unit tests, with another process and a killed holder, and with two real console processes (§CC). A file system without such locks (some network shares) gives no protection.
- **Open question #43, the refresh's free space:** the refresh checks no free space before it starts; the measured peak (§BD) is in the `v0.1.1` notes' known limitations and the README.
