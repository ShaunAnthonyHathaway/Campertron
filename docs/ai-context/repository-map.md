## Solution
`Campertron.sln` [V] contains 8 projects: `CampertronConsole`, `CampertronLibrary`, `CampertronGUI`, `CampertronUnitTests`, `CampertronGUITests` (added with the Avalonia 12 migration), `docker-compose` (`docker-compose.dcproj`) and, since D92, `CampertronWeb` and `CampertronWebTests`.

Project references [V] (from the `.csproj` files):
```
CampertronConsole   ──► CampertronLibrary, CampertronWeb
CampertronWeb       ──► CampertronLibrary
CampertronGUI       ──► CampertronLibrary
CampertronUnitTests ──► CampertronLibrary
CampertronGUITests  ──► CampertronGUI ──► CampertronLibrary
CampertronWebTests  ──► CampertronWeb, CampertronConsole
```
Only `CampertronWebTests` references `CampertronConsole` (it starts the console's own program as a process, D92). Only `CampertronGUITests` references `CampertronGUI`.

## Projects

### CampertronConsole (`CampertronConsole/CampertronConsole.csproj`)
- Exe, `net11.0`, `Nullable` enabled, `DockerDefaultTargetOS=Linux` [V]. Packages: Azure Containers Tools Targets 1.22.1 [V]. Since D92 it references `CampertronWeb`, whose framework reference makes its outputs carry or name `Microsoft.AspNetCore.App` beside `Microsoft.NETCore.App`. EF Core Tools and a redundant FileProviders.Embedded reference were removed in D31 (the library brings everything the console uses).
- `Program.cs` [V]: `--version` (exactly that one argument) prints `RuntimeInfo.Describe` and returns 0; since D92 web mode's arguments go to `CampertronWeb.WebMode.Run`; since D121 `ConsoleArguments.Parse` decides `--help` (`WriteHelp`, 0), `--interactive` (`InteractiveConsole.RunInTerminal`) and their refusal (1); otherwise it sets `Load.FirstStartNotice` and returns `Load.RunConsole(Load.GetConfig())` inside a `try` (since D64: 1 when email mode had no search to check, 0 after an `outputTo: UnitTest` start): a failure is reported by `ConsoleUi.ReportFailure` (standard error; since D67 with all the run's settings, so the SMTP passwords and ntfy's token and topic are hidden) and `Main` returns 1 (D34). Since D92, between the two: a command line with one of web mode's arguments (`WebMode.IsRequested`) returns `CampertronWeb.WebMode.Run(args)`. No other argument parsing.
- `Dockerfile` [V]: multi-stage, multi-architecture build. `mcr.microsoft.com/dotnet/sdk:11.0` runs on `$BUILDPLATFORM` and restores, builds and publishes the console with `-a $TARGETARCH` (framework-dependent, `UseAppHost=false`); the final stage is `aspnet:11.0` since D92 (`runtime:11.0` before; Ubuntu 26.04 since D31), with `EXPOSE 8790`, the web UI's port, and no default command (web mode is opt-in: `--web`); the restore step copies `CampertronWeb.csproj` too. `COPY . .` brings the root `global.json` into the build stage, so the build and publish steps resolve the image's SDK 11 through the same policy. `VERSION`/`REVISION` build args and OCI labels (title, description, source, MIT license, version, revision). `ENTRYPOINT ["dotnet", "CampertronConsole.dll"]`; `USER app`. Needs BuildKit.
- `Properties/launchSettings.json` [V]: profiles `CampertronConsole`, `WSL`, `Docker`.

### CampertronLibrary (`CampertronLibrary/CampertronLibrary.csproj`)
- `net11.0` [V]. Embeds `content/RecreationDotOrg.db.br` as an `EmbeddedResource` [V]. It is the Brotli-compressed `RecreationDotOrg.db` (26,616,039 bytes; 226,471,936 bytes extracted; SHA-256 of the DB `8712856097a91ee1…`), built from the RIDB export of 2026-11-10 with only the 6 used tables. It replaced `content/RecreationDotOrg.zip` (81,232,118 bytes, holding a 328,126,464-byte DB dated 2024-11-18).
- Packages [V]: EF Core Sqlite 11.0.0 (brings Microsoft.Data.Sqlite 11.0.0, SQLitePCLRaw 3.0.5 and the native `SQLite` 3.53.4 package), FileProviders.Embedded 11.0.0, Newtonsoft.Json 13.0.3, YamlDotNet 16.3.0 (D31; EF Core Tools removed).
