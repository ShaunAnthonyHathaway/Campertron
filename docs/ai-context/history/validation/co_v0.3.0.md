A page's view is a 16-hex signature of what its controls and parts show (`WebLive.Signature`); when an answer's view differs, or the operation ended, the script takes `?handler=view` (the page as a GET shows it, without an action's notice, the system page never its confirmation) and replaces the parts of `#live-view` whose `data-part` name changed, or that have none, or that hold `#live`; a part with an unchanged name stays, with the focus in it.
Rejected: a page per operation with its own script (duplicated state machines and checks), Server-Sent Events (as §CU), renewing the session (an open monitoring page would keep a browser signed in for the 7-day lifetime), and replacing the whole page at every check (the monitoring's Stop and the focus on it would be replaced twice a minute).

**Lifecycle, ownership and the refresh** [V]: the refresh is the web UI's (D99): every signed-in session sees and may follow it, as it sees the page; its key is this start of the web UI's random name and the refresh's number. A key of this start whose refresh is no longer running is "ended" (refreshes run one after the other); another start's key, a number no refresh had, a non-canonical number or no key is "replaced" with nothing of a refresh. The observer takes one immutable view: it starts, cancels, pauses, repeats, resumes and installs nothing and reads `General.yaml` only as a GET does. Unchanged: the one-at-a-time gate with the results page, Cancel until the cache step (finishing from there, Cancel answered "too late"), the installation, the database's integrity (the service's, `RidbRefreshServiceTests`), the settings and search files, the fixed words, the download.

**Security analysis:**
- Every request of the script passes the existing checks in their order (GET, Host, the rate limits, the sign-in, the owner policy); no new anonymous address (`/assets/live.js` replaces `/assets/results.js`, the same owner-only literal route); the Content-Security-Policy unchanged; no CORS header; no POST from the script; Cancel, Start, Stop and Restart the pages' own POSTs with the antiforgery token and the moment the page showed, then a redirect.
- The answers hold only what the page shows (status, progress line, counts, the bar, the monitoring's check line and countdown); never a path, a file's content, a setting, a secret, an exception's message or another session's run; JSON with markup characters escaped; the script sets text and attributes only and puts in place only the web UI's own rendered parts, parsed inert.
- Sessions: a page's own requests never renew the idle time (8 hours) on any live page; a session that ends gets the sign-in for its next question, which the page reports and stops at; the results page's run still ends with its session.
- Rate limits: an open live page asks 30 times a minute, of the client's 240; a client over its limit gets the fixed 429 page, which the page reports as a failed update and backs off from.

**Order, generations and terminal states:** each answer's number is one higher than the session's last; a page applies one only for its key, only when its number is higher than the page's and its rank not lower (results: running 1, canceling 2, ended 3; refresh: running 1, canceling 2, finishing 3, ended 4; monitoring: 0). The end (ended, a refresh's or a run's; for the monitoring, not running and not starting again by itself) takes the page once and stops; a "replaced" answer, a sign-in, a sent form or a left page stop it. A page of an operation that does not go on has no script.

**Failure and recovery:** as §CU for the three pages, each in its operation's words ("That does not stop the refresh (the monitoring)"); the page itself not obtainable after a change or the end: "can't show how it ended right now, and it keeps trying" at the end, the failing words otherwise; a recovery said once ("This page gets the … again."). A web UI restarted: its new instance name makes a still-signed-in page "replaced"; in practice a restart ends every session, so the page reports the sign-in.

**Accessibility:** focus and scroll never moved by an ordinary update; after a part is replaced, the focus on the same control, else the status (`tabindex="-1"`, without scrolling); the monitoring's actions part, and the focus on Stop, unchanged while checks go on; the status line without a live role while the script updates it; one polite, atomic region outside the replaced part, for the first warning, the recovery, a change of state (Cancel, the cache step, a start, a stop, a pause) and the end only. A part that gets shorter (a later check with no openings) can shorten the page, and the browser then keeps the scroll within it.
