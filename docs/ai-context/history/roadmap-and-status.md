### 3.2 `CLAUDE.md` §Architecture in one paragraph

The paragraph that followed the heading `## Architecture in one paragraph`:

Everything lives in static classes in `CampertronLibrary`. Config (`Load.GetConfig`) picks paths: `/config` + `/cache` in a container, otherwise `LocalApplicationData/CampertronConfig` + `/CampertronCache`. It loads `General.yaml` and `Email.yaml` and ensures `RecreationDotOrg.db` exists. If an installed DB has the swapped 2024 layout, or is a pre-0.1.0-beta.4 DB that still has the omitted tables, a one-time startup repair replaces it with the bundled DB (`LegacyAddressLayout.RepairIfNeeded`, business-rules §8). The trigger is a property of the DB, never the app version, and a valid DB is never replaced. Search (`Load.RunConsoleSearch` → `Preload` → `AvailabilityApi.GetAvailabilitiesByCampground` in parallel per config → `PostProcess`) fetches monthly availability JSON from recreation.gov and filters it with the rules in `AvailabilityApi.FilterData`.
It renders through a `ConsoleConfigValue` list that `CampsiteConfig.ProcessConsoleConfig` writes to the console or turns into HTML and email. Static RIDB data (campsites, equipment, attributes, facilities) comes from SQLite through `sqlite/Read.cs` and is cached as per-campground JSON in the cache dir. The eight include and exclude lists are matched by `SearchFilters` (D51: OR semantics, the search's `filterMatching`, Exact or Contains); `Read.FilterChoicesByCampground` gives a campground's filter choices, and `RidbIndexes` owns the database's only secondary index (attributes by campsite), ensured at a start and built by the refresh. `YamlDocument` (`function/Base/YamlDocument.cs`, D39) edits a settings document's text in memory by targeted range replacement, keeping comments and formatting, and checks every result with the loaders' own deserializer (`Yaml.SettingsDeserializer`).
Every settings file is read through `Yaml.ReadSettingsText`/`LoadSettingsText` within the editor's limits, and `ConfigFiles` decides which file is which (D41); `ConfigValidation` (D41) turns settings into typed, value-free diagnostics, refuses at start only dangerous settings, and checks `Email.yaml` before the Email loop searches. `ConfigFileReplace` (D40) is the only way a settings file is written: `Replace` (strict UTF-8, verified temporary file, mode, links, backup, external-change check, rename) for `General.yaml`'s refresh timestamp, which `Yaml.GeneralConfigReplaceYaml` edits with `YamlDocument`, and create-only `Create` for the sample files. The GUI's window has four top-level tabs, Searches, Results, Settings and Campgrounds (D50; the fourth labeled Campgrounds since D55; Settings holds Campertron and System, Campgrounds the three lookup tabs). Settings > Campertron edits `General.yaml` and `Email.yaml` through `ConfigEditSession` (D43:
the bytes read, pending typed edits, `YamlDocument` steps, `ConfigValidation`, a masked preview, `ConfigFileReplace.Replace`, external-change conflicts), and its Searches tab the search files through the same session (`ConfigEditSession<CampertronConfig>`, D44), with New search (`SearchFiles.Create`) and Save As (`SaveAs`), both `ConfigFileReplace.Create`, and a campground picker from `Read.CampgroundPickerEntries` (every reservable, enabled campground, one query). The GUI's Results tab (D46) is that host: `ResultsViewModel` lists the search files (`CampsiteSearch.LoadEntry`, the plan's own reading), runs the chosen ones through `CampsiteSearch.Plan`/`Run` on a background thread with a `ProgressGate` (newest snapshot, at most ten UI updates a second) and presents the typed results (`ResultRows.cs`) in `ResultsView`. A host other than the console searches through `CampsiteSearch` (`function/RecDotOrg/search/`, D45):
`Plan` reads and checks chosen search files, `Run` runs each through the console's `AvailabilityApi.GetAvailabilitiesByCampground` with a per-run `SearchHost` on `RunningData.Host` (cancellation, the transport seam, at most three requests per month, blocks, the shared months' signals, progress; null for the console) and builds immutable typed results (`class/Base/SearchRunModel.cs`) from the output values' metadata. The GUI lists campgrounds as `CampgroundChoice` entries (`class/RecDotOrg/CampgroundChoice.cs`: FacilityID, name, optional location; D42) from `Read.CampgroundChoicesByPark`/`ByStateAndCity`/`ByState` and loads their details with `Read.GetCampgroundDetailsById`. Details: `docs/ai-context/architecture.md`.
