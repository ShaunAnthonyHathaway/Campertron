# Console → GUI map

Legend: **[V]** verified · **[I]** inference

GUI facts come from `CampertronGUI/Views/MainWindow.axaml(.cs)`, `Views/CampgroundDetailsView.axaml(.cs)`, `Views/StartupStatusView.axaml(.cs)`, `ViewModels/ReactiveViewModel.cs`, `ViewModels/CampgroundDetails.cs`, `ViewModels/MainWindowViewModel.cs`, `SmokeTest.cs`, `Program.cs` and `App.axaml(.cs)`. The GUI has no `ReactiveCommand` [V]. Its interactions are `ComboBox` selections (with type-ahead) across three lookup tabs, selecting text, scrolling the details, one **Copy ID** button (a `Click` handler in `CampgroundDetailsView`, beta.8), after a failed startup **Try again** (R8) [V], since D43 (CM5) the **Settings** tab, which edits `General.yaml` and `Email.yaml` (business-rules §17; `ViewModels/Settings*.cs`, `Views/Settings*.axaml`, `SecretTextBox`) [V], and since D44 (CM6) the **Searches** tab, which creates and edits search files (business-rules §18; `ViewModels/Search*.cs`, `CampgroundPicker.cs`, `Views/Search*.axaml`, `ListFieldView`) [V]. The lookup tabs stay read-only; the GUI runs no search and shows no results.

| Console workflow (feature-inventory ID) | GUI status | Evidence |
|---|---|---|
| F1 Startup / first-run bootstrap (dirs, sample YAML, DB extraction, auto-refresh) | **Implemented** (shared code) | Since R8 (D33) `MainWindowViewModel` calls `Load.GetConfig()` on a background task after the window has opened [V]; the same library method as the console, so the side effects are identical. Meanwhile the window shows "Preparing campground data…"; a failure (for example an invalid `General.yaml`) is shown in the window with the message, the settings folder and Try again, instead of aborting the process. The tabs and their database-backed `ReactiveViewModel` exist only after it succeeded, with its `ConfigPath`. Before R8 it ran in the `MainWindow` constructor, before any window existed, and its result was unused |
| F2 Interactive menu | **Not implemented** | No menu equivalent. The GUI is a `TabControl` with "By Park", "By City", "By State" [V] |
| F3 Search with console output | **Not implemented** | No reference to `RunConsoleSearch`, `AvailabilityApi` or `Preload` in `CampertronGUI/**` [V, grep]. There is no availability display |
| F4 Search with HTML output | **Not implemented** | Same evidence as F3 |
| F5 Headless email loop | **Not implemented** | No reference to `EmailConfig` or `ProcessConsoleConfig` in the GUI [V] |
| F6 Refresh RIDB data | **Partial** | No user action. It can only happen as a side effect of `Load.GetConfig()` → `DbExistsCheck` when `autoRefresh: true` and the interval has elapsed [V]. That path writes progress to `Console`, which a WinExe does not show [I]. Since D26 it is failure-safe: a failed or interrupted refresh leaves the GUI's DB unchanged, and the GUI's own open or pooled connections need not close for the installation (business-rules §8). Since R8 it runs on a background task while the window shows "Preparing campground data…" (it used to block before any window existed); a failed refresh is shown in the window with Try again, and a refresh still running when the window closes is allowed to finish before the process exits (`Program.Main`). A failed refresh is retried on the next start because the timestamp is no longer written before the refresh |
| F7 View Config | **Partly (D43)** | The Settings tab shows the settings folder and each file's path, opens the folder (Open settings folder) and shows `General.yaml`'s settings, the refresh interval and the last refresh; no refresh age or OS info. Also the settings folder in the startup-error state (R8). Since R8 `ReactiveViewModel.ConfigPath` is `Load.GetConfig`'s path (it replaced `GetConfigPath`) and is not bound in XAML [V] |
| F8 Exit | **Unclear** | No explicit exit action. Window close is handled by Avalonia's classic desktop lifetime (`StartWithClassicDesktopLifetime` in `Program.cs`). Not an equivalent workflow |
| F9 Container mode | **Not implemented** | The GUI is not supported in a container. Since R8 it queries `Load.GetConfig`'s own `ConfigPath` (before R8 it was hard-coded to `LocalApplicationData/CampertronConfig`, which differs from `/config` in container mode) [V] |
| F10 Search-config discovery and editing | **Implemented in the GUI (CM6, D44)** | The Searches tab lists the console's search files (the same discovery, `ConfigFiles.SearchFiles`, sorted by name) with each file's search name, whether it runs (autoRun), its campground and its state, and edits the chosen one: every setting typed, the dates and the eight filters as rows, the validation's problems at their fields and rows, a read-only preview of the changed lines, Save, Revert, Reload, conflicts for changes by another program, New search (the example search, disabled) and Save As (create-only). The campground is chosen from every reservable, enabled campground or by its exact ID (TD-53 resolved). Comments and formatting stay (the CM1 editor, the CM2 writer, D39/D40). Nothing deletes a file or runs a search (business-rules §18). The console still edits search files only in a text editor [V] |
| F11 Duplicate-notification suppression | **Not implemented** | Not applicable without search |

## GUI-only features (no console equivalent)
| GUI feature | Implementation [V] | Notes |
|---|---|---|
| Browse by Park (RecArea) → Campground → details | `ParkList` → `Read.ParksWithCampgrounds`, `CampgroundListByPark` → `Read.CampgroundChoicesByPark` (`CampgroundChoice` entries), `SelectedCampgroundByPark` → `ParkCampgroundDetails` → `Read.GetCampgroundDetailsById` (since D42; before: `UniqueCampgrounds`, `UniqueCampgroundsByPark` and `GetCampgroundDetailsByName`) | Since D42 a park's campgrounds without an address are listed too (without a location); every entry shows its location and ID (business-rules §16) |
| Browse by State → City → Campground | `StateList` → `Read.UniqueStates`, `CityList` → `Read.UniqueCities`, `CampgroundList` → `Read.CampgroundChoicesByStateAndCity` (since D42; before `UniqueParks(state, city, path)`), `SelectedCampground` → `CityCampgroundDetails` | An empty city is listed as "(No city listed)" (display only, `DisplayConverters.City`); the stored empty value is selected and queried |
| Browse by State → Campground | `StateListByState` → `Read.UniqueStates`, `CampgroundListByState` → `Read.CampgroundChoicesByState` (since D42; before `UniqueParksByState`), `SelectedCampgroundByState` → `StateCampgroundDetails` | Each tab keeps its own selections and details since beta.8 (TD-08 fixed); a filter change clears the tab's campground (D42) |
| `--version` | `Program.Main` → `RuntimeInfo` (same as the console, F13) | Prints the version and .NET runtime and exits before Avalonia starts. On Windows (WinExe) only visible when redirected [A] |
| Settings tab (CM5, D43) | `SettingsViewModel` → `GeneralSettingsViewModel`/`EmailSettingsViewModel` → `ConfigEditSession` → `YamlDocument`, `ConfigValidation`, `ConfigFileReplace` | Typed forms for every setting of `General.yaml` and `Email.yaml` with their problems, a read-only preview of the lines a save changes (password masked), Save/Revert/Reload, Create for a missing file, conflict choices for changes by another program, a masked password with a temporary on-screen reveal, recipients as rows, Open settings folder (business-rules §17). The console has the same settings in the same files (edited in a text editor) |
| Searches tab (CM6, D44) | `SearchesViewModel` → `SearchFileViewModel` → `ConfigEditSession<CampertronConfig>`; `CampgroundCatalog` → `Read.CampgroundPickerEntries` | The search files with their state, New search, Save As, the search editor with the campground picker and exact typed IDs, the folder's "no search runs" warning (open question #40 unchanged); no search, no availability results (business-rules §18) |
| `--smoke-test` (R8, D33) | `Program.Main` → `SmokeTest.Run` | A normal start that reports each step as `SMOKE key=value` and exits 0 only if the window opened with a native handle, the startup became ready, a frame rendered, data is there, the settings editor's probe passed in a temporary folder and both settings files open in the Settings tab (D43), the search editor's probe passed and the Searches tab showed the campground data (D44), and the window closed cleanly (1 failure, 2 timeout after 60 s). Used by the release smoke tests on Linux, Windows and macOS (build-and-test.md §X); redirected output works for the WinExe |
| Startup states (R8, D33) | `MainWindowViewModel`, `StartupStatusView` | "Preparing campground data…" with a progress bar; an error state with the selectable message (YAML line and column), the settings folder, advice to fix or delete the file and Try again |
| Campground details (`CampgroundDetailsView`, shared by the three tabs) | Binds a `CampgroundDetails` snapshot built from `Read.GetCampgroundDetailsById` (the selected entry's FacilityID, since D42; unprefixed values, HTML converted by `Read.HtmlToPlainText`): title, the tab's filter context, "Campground ID" with a selectable ID and **Copy ID**, Contact (Phone, Email), Description, Directions, Fees; "Not listed" for missing values; an empty state before a campground is selected. The GUI owns all labels (D28) | This is how users get the `campgroundID` for a search YAML (README). Since D42 the lookup is by FacilityID, so campgrounds with the same name show their own details (TD-38 resolved); a blank name shows as "Unnamed campground" |
