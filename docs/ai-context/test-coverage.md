# Test coverage

Authority: current. This file is the only current authority for Campertron's tests: the test projects, every test class with its discovered numbers of tests and cases, the tests that skip on a platform, which tests cover each feature and what each test checks, and how the unit, GUI, release-policy, documentation-policy and platform validation differ. Other current documents name test classes only as pointers to this file; earlier counts are historical and stay in the validation records (`history/validation/`). The commands and test warnings, the validation baseline and the checks to run after a change are `build-and-test.md`'s; the test projects' packages and helper files are `repository-map.md`'s.

Roadmap step 9, Phase 4 (2026-11-17) built this file from the test tables and lists of `feature-inventory.md` and `repository-map.md` (moved here, `history/README.md` §Phase 4 migration map) and from a new discovery of the tests.

## What is not covered
The console's behavior on a real terminal (the menu's keys and cursor, Ctrl+C, redirection, the container) is not covered by unit tests; it is checked with the pseudo-terminal matrix of history/validation/x-ac_preview.1.md §Y, on Linux only. On Windows the maintainer reviewed the D34 output manually before PR #49 was merged and reported that it looked good (a maintainer-reported manual visual review, not an automated or comprehensive check); macOS was not run (open question #38).

There are no tests for: `AvailabilityApi`'s other filter conditions one by one (since D51 `SearchFiltersTests` and `FilterSemanticsTests` test the eight include and exclude lists; people, dates and weekdays are checked through the search suites), `GetConsecutiveDays` on its own (since D35 `SearchDatesTests` cover `CampertronConfig.GenerateSearchDates`/`GetMonthsOut`, and `SearchIsolationTests` consecutive filtering in shared runs), `Calendar`, `Yaml`, `Read` (other than the address/state queries and the details lookups above), `Cache` beyond the cache-path tests above, the download of the real RIDB export (since D61 the download and extraction are tested against an in-memory server, `RidbRefreshServiceTests`), actually sending email or how email clients show the page, or the menu's drawing (its keys: `MenuKeysTests`, D47). The GUI is tested automatically on Avalonia's headless platform;
the real Linux window was checked manually for beta.8 and R8 (history/validation/a-w_2026-11-10_to_beta.10.md §P, history/validation/x-ac_preview.1.md §X), and since R8 every release run starts the published GUI natively on linux-x64, win-x64, win-arm64, osx-x64 and osx-arm64 with `--smoke-test` (no screenshots), since S2 (D48) also on linux-arm64, and the win-x86 GUI as a 32-bit process on 64-bit Windows.
